## Findings

1. **P1 release completeness: the tutorial repair is absent from a normal source checkout.** `deploy/game_content/content/tuto/tuto8.txt` contains the additional line 23 `PLAYWAIT 0.5`, but `git check-ignore` confirms it is ignored. No maintained generator or regression under `scripts/` reproduces this specific change. Shipping repository changes alone can leave the known fresh-account freeze unfixed. Add a narrow, hash-checked, idempotent maintained application step and validate its output. This review does not change the live content file.
2. **P2 robustness prerequisite: fixed-delay tutorial repair has limited acceptance.** The documented defect is a modal callback removing the tutorial tap area after its creation. The current change delays creation by 0.5 script seconds; it does not itself establish a request/scene completion condition. Recorded normal-speed runs pass. Delayed response/load cases and whether the timer pauses under the modal are unproven. This is a validation gap, not a newly reproduced freeze. Require a controlled delayed-response test and a lifecycle-based correction if needed.
3. **P2 reproduced audit crash.** `scripts/check_mst_bootstrap.py:staged_rows` reads `m.get` before checking that `m` is a dictionary. Independently reproduced on October 27 with isolated manifests containing `[]`, `null`, `1`, and a JSON string; all raise AttributeError. Evidence: `out/qa/current/qc_20261027/audit_malformed_repro.log`. Validate shape before member access and add negative tests.
4. **P2 startup coverage remains incomplete.** The area source-ordering proof and two C8 alias decisions identified in `QC_SESSION_19_REVIEW.md` are still outstanding. A warm route is not proof of every initial/version-refresh path. The real-tree live test still reports incomplete with eight absent names and correctly keeps the census and prompt. Do not force completeness or remove initialization to close this milestone.
5. **P2 release tests depend on ignored tools.** The full runner names `tools/bin/x86_startup_rules_check.py` and `x86_mst_bootstrap_check.py`, both ignored. Their transitive helpers must also be accounted for. A release needs maintained checker sources or an explicit reproducible tooling dependency, not an undocumented `out`/local-tools dependency.
6. **Documentation correction:** `standalone_frontend/main.cpp` still attributes the title login hang to idle socket expiry. The later controlled visual diagnosis identifies QuickEdit blocking console writes and records successful late login using the old server. Socket retention was separately tested, but that does not prove it caused the hang. Correct the causal comment without casually reverting behavior.

The console queue is bounded at 1,000 lines, releases its lock before `WriteConsoleW`, and removes the old synchronous hook prints. The proxy unit target does not compile `console_log.cpp`, so its 677 passing checks are not a direct console-queue test. The held-console control/acceptance is recorded visual evidence from October 23. Add a focused regression if changing this code further.
