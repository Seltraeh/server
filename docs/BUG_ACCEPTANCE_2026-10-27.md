## Additional findings and recent fixes

The October 23–24 handoff records six fixes: fresh-account world gating, Terms readability, idle socket retention, console-induced login freeze, tuto8 input loss and the mission-2 summon checkpoint. The console diagnosis supersedes the earlier claim that timeout caused the title hang; round 1 corrected the stale comment in `standalone_frontend/main.cpp` (behavior unchanged).

**tuto8 quest-select freeze (Fix E), round 1.** The race is reproduced and the correction is validated under delay. With both quest-select replies held 5 s at a relay, the shipped script (`cfa85733…`) froze exactly as reported: no arrow after the release and no response to taps. The corrected script (`271511d9…`) drew its arrow only after the release and kept it, and so did the mission select's own held round trip. The cause is now established statically: `PLAYWAIT` counts script frames (arm64 `AdventureSystem::advPlayWait`: param × 60, one per `advPlay`), and the quest select gets no frame while the modal `ConnectScene` is the running scene. So the delay holds for any response time, as long as the request still goes out within 30 frames (it goes out on frame 2). The correction is now reproducible: `scripts/apply_content_patches.py` is hash-checked, idempotent and refuses unknown bytes, with `scripts/test_content_patches.py` (13/0) registered in the runner. The live content root was only read. Not covered: a cold first visit with the quest select's assets absent; the run's assets were already cached. The x86 frame-pause was observed (A/B result), not traced in x86 code.

**Bootstrap audit shape crash, fixed.** `scripts/check_mst_bootstrap.py` now checks the manifest shape and field types as MstVersions.hpp's Glaze read does. Thirteen malformed or wrongly typed manifests are covered: offline 36/0, and live against `c9405702` 49/0, where the running server announces none of them. The old code still raises AttributeError on the same tree (control).
